01 — The Challenge

Understanding the Spanish Electricity System

Electricity demand and generation change continuously. Understanding these changes requires looking at historical trends, the contribution of different energy sources and the connections between electricity systems.

For this bootcamp final project, I worked on an interactive dashboard designed to make Spanish electricity system data easier to explore. The goal was to bring together data analysis and visualization in one application, while also experimenting with time-series forecasting techniques to estimate future electricity demand.

The project combines two main areas: an exploratory analysis of historical electricity data and a machine learning section dedicated to demand forecasting.

02 — The Data

Working with Real-World Energy Data

The project uses electricity system data from Red Eléctrica de España (REE), the Spanish electricity system operator. The data provides the basis for exploring historical demand, electricity generation and exchanges between regions and neighboring systems.

The application brings together several perspectives on the electricity system:

  • Electricity demand: exploring how demand changes over time and across selected periods.
  • Generation by technology: examining the contribution of different energy sources to electricity generation.
  • Electricity exchanges: visualizing exchanges between regions and with neighboring countries.
  • Historical comparisons: comparing annual trends and changes in the electricity system.

The project also uses a MySQL database to store and organize the data used by the application. Database creation and population are handled through dedicated Jupyter notebooks.

03 — The Approach

From Data Preparation to Interactive Exploration

Data preparation and storage

The workflow combines data retrieval, preparation and storage before presenting the information through the dashboard. Python and Pandas support data manipulation, while MySQL provides the database layer. This structure separates data preparation from the interactive interface.

Interactive data visualization

The dashboard is built with Streamlit and Plotly. Users can explore electricity demand, compare annual data, inspect generation by technology and visualize electricity exchanges through interactive charts and maps.

The application is organized into sections for the main dashboard, data analysis, machine learning and project information. This makes it possible to move from understanding historical patterns to exploring forecasting experiments within the same interface.

Experimenting with forecasting models

The machine learning section explores four approaches to time-series forecasting:

  • Simple RNN: a recurrent neural network used to learn patterns from sequential data.
  • LSTM: a recurrent neural network architecture designed to learn longer-term dependencies in sequences.
  • GRU: another recurrent architecture that uses gating mechanisms to model sequential patterns.
  • Prophet: a forecasting approach designed for time series, used here to generate future demand estimates.

The dashboard allows users to explore forecasts over different horizons, including 7, 15 and 30 days. The recurrent models also distinguish between two prediction strategies.

One-step forecasting predicts an observation from a historical input window. Recursive multi-step forecasting generates successive predictions by feeding earlier predictions back into the forecasting process. This distinction matters because errors can accumulate as the forecast horizon increases.

Model performance is explored using metrics such as the coefficient of determination (R²), mean absolute error (MAE) and root mean squared error (RMSE).

04 — Results

Exploration, Forecasting and Model Evaluation

The final application brings together interactive historical analysis and demand forecasting experiments in a single dashboard. It provides different ways to explore the electricity system, compare periods and technologies, and inspect model-generated demand estimates.

The experiments also illustrate that forecasting performance depends on the model and the prediction strategy. Predicting the next observation and recursively forecasting several steps ahead are different tasks, and their metrics should be interpreted separately.

Selected experimental metrics

The following values are taken from the project's recorded model metrics. They are presented as experimental results rather than as a definitive ranking, because the evaluation and scaling procedures have not been fully verified as identical across models.

Recurrent neural networks

Model Prediction strategy R² MAE (GWh) RMSE (GWh)
RNN One-step 0.40 34.53 42.39
RNN Recursive multi-step -25.90 61.52 75.85
LSTM One-step 0.31 34.68 41.67
LSTM Recursive multi-step -143.24 63.68 78.53
GRU One-step 0.784 12.89 15.77
GRU Recursive multi-step 0.305 22.30 28.28

In the recorded experiments, the GRU one-step results show lower errors than the listed RNN and LSTM one-step results. The recursive multi-step results also show how performance can deteriorate when predictions are generated sequentially.

The strongly negative R² values recorded for the RNN and LSTM multi-step experiments indicate poor performance relative to a simple baseline based on the mean of the evaluated target values. These results are useful reminders that a model that produces reasonable short-term predictions may behave very differently over a recursive forecast.

Evaluation note: these metrics reflect the project's recorded experiments. The available code does not establish that every model was evaluated on an identical target scale and test procedure. In particular, the recursive implementations and the Prophet evaluation require further verification before a direct cross-model ranking can be considered reliable.

Prophet experiment

Two Prophet metric configurations were recorded in the project:

Configuration R² Recorded MAE Recorded RMSE
con 0.8294 0.0512 0.0682
sin 0.7727 0.0567 0.0787

The configuration labelled “con” has the higher recorded R² and lower recorded MAE and RMSE. However, the available implementation does not establish what the “con” and “sin” labels represent, nor does it confirm that these errors use the same scale as the recurrent-model metrics. For that reason, the Prophet values are reported separately and are not directly compared with the errors expressed in GWh above.

05 — What I Learned

Key Takeaways

  • Working with real-world data: gaining practical experience preparing and organizing energy-system data for analysis.
  • Building data applications: connecting a database, data processing and interactive visualizations in a Streamlit application.
  • Exploratory data analysis: using historical comparisons, interactive charts and maps to investigate electricity demand, generation and exchanges.
  • Exploring time-series models: working with recurrent neural networks and Prophet to investigate different approaches to demand forecasting.
  • Evaluating model performance: using R², MAE and RMSE to examine predictions and recognize the importance of consistent evaluation procedures.
  • Understanding forecasting limitations: learning that recursive predictions can behave differently from one-step predictions, and that reliable comparisons require careful validation of the data pipeline and evaluation setup.

This project gave me the opportunity to connect several stages of a data workflow, from database preparation and exploratory analysis to interactive reporting and machine learning experimentation.
